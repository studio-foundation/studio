# Onboarding — {{PROJECT_NAME}}

How to go from a fresh machine to a working run of this project. Generated by
`studio init`; edit it freely — nothing regenerates over it.

## 1. Install Studio

Studio is a global CLI, not a project dependency. The standalone binary needs no Node.js:

```bash
curl -fsSL https://raw.githubusercontent.com/studio-foundation/studio/main/install.sh | sh
```

On Windows, PowerShell:

```powershell
irm https://raw.githubusercontent.com/studio-foundation/studio/main/install.ps1 | iex
```

Or from npm, if this machine already has Node.js >= 22.13:

```bash
npm install -g @studio-foundation/cli
```

## 2. Get the project

```bash
git clone <this-repo>
cd {{PROJECT_NAME}}
```

Install the app dependencies too, if this project has a `package.json`:

```bash
npm install
```

## 3. Create your local config

`.studio/config.yaml` holds the real values and is gitignored. `.studio/config.example.yaml`
is its committed twin — every key left uncommented there is required.

```bash
cp .studio/config.example.yaml .studio/config.yaml
```

Then fill in what it asks for. Secrets belong in environment variables, referenced
from `config.yaml` as `${VAR}` — never written in the file.

## 4. Check the machine

```bash
studio doctor
```

One command, four checks: the installed Studio satisfies the project's
`studio_version`, `config.yaml` has every key the contract declares, every required
binary is on PATH and in range, and every `${VAR}` resolves to a non-empty value.
Exit code is `1` on any failure, so it also works as a CI gate.

Fix whatever it prints, re-run it, and only then run a pipeline.

## 5. Run

```bash
studio list pipelines
studio run <pipeline> --input "..."
```

Useful while getting oriented:

```bash
studio run <pipeline> --provider mock    # no API calls, no key needed
studio run <pipeline> --live             # stream tool calls as they happen
studio status                            # last run
studio logs <run-id>                     # raw JSONL for a run
```
