# Plan — STU-1260: Name the child pipeline in a map stage's header line

Path: fallback (trivial ticket) — no shaping bundle; planned directly from the issue text and the
real MapStartEvent/map-orchestrator/ProgressDisplay/MapRenderer/run.ts code.
Scope: `MapStartEvent` gains the sub-pipeline name (additive), populated by the map orchestrator,
rendered in the fan-out header, and carried into the run's JSONL log.

## Reachable-surface classification (per CLAUDE.md's semver rule)

New field on an event a config author never writes (`map_name` etc. are emitted, not authored) →
no `.studio/` YAML surface changes → **PATCH**, not MINOR, despite being a new field. Noted here so
the eventual bump-version pass doesn't misclassify it.

## Changes

1. `engine/src/events.ts` — add `pipeline?: string` to `MapStartEvent` (optional: additive, an
   event consumer that doesn't care is unaffected, matches the issue's own framing).
2. `engine/src/pipeline/map-orchestrator.ts` — populate it at the `onMapStart` call site
   (`this.config.events?.onMapStart?.({ map_name: map.map, ..., pipeline: map.pipeline })`);
   `map.pipeline` already exists on `MapStage` (`contracts/src/pipeline.ts`), no new type needed.
3. `cli/src/output/map-progress.ts` — `MapRenderer.start()` gains a `pipeline` parameter, header
   line becomes `↳ ${mapName} → ${pipeline} — fan-out over N items...` when present, unchanged
   (`↳ ${mapName} — fan-out...`) when absent (keeps the synthetic-event unit tests in
   `progress-nested.test.ts` passing unmodified — they build `MapStartEvent`s without `pipeline`).
4. `cli/src/output/progress.ts` — `onMapStart` handler passes `event.pipeline` through to
   `renderer.start(...)`.
5. `cli/src/commands/run.ts` — the JSONL `log()` call in `onMapStart` gains `pipeline: e.pipeline`,
   so the run's `.studio/runs/<run>.jsonl` carries it. This handler has no `jsonMode` guard (only
   `ProgressDisplay`'s own `onMapStart` does), so the JSONL gets the field under `--json` too —
   satisfies the issue's "a check that `--json` output and the run JSONL carry the new field"
   without widening `MapStageOutput` (the final `--json` stdout dump), which the issue's own
   "Desired end state" never asks to change — only `MapStartEvent` does.
